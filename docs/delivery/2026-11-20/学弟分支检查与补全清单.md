## 整改顺序与交付边界

优先补 O1、O2、O4、H1、H2 中需要实际原件支撑的复现能力，及 Y1 的入口矛盾。共享大型载荷按许可和可取得性安排，先查本人保存的原件。随后补 Y2、Y3、O3、O5、H3、H4 的出入口与既有证据对应。每个问题的确认、仍待核实及不适用项可在各分支正式说明中记录。三条分支在本轮只完成 GitHub 和现存项目证据范围核查，任何学弟整改、访问权限确认和需要实算的补验证由后续对应负责人完成。
