# GRID Instruments RQ-KMeans

The source anchor is `bc6176dc144b827b1b29f73ad3b216e28b39f48f`, under `Baseline Results/Instruments GRID Qwen`. The files in `reference/` preserve the source commands, configs, Qwen worker and selected execution records. `reference/native_blobs.tsv` lists the Git blob ID of each frozen file under `native/`.

`upstream.py` builds a fresh single-shard TFRecord on the common catalogue. It checks the item IDs, archived Qwen text hashes and every float32 embedding row against the identity bridge. It writes and reads back every TFRecord row. The fit and inference subprocesses use the original `rkmeans_train_flat` and `rkmeans_inference_flat` Hydra configurations and the source `grid_stage.py` entrypoint. `runtime.py` records resolved configuration, actual fit batches and per-layer centroid changes, strict checkpoint load and prediction item IDs. The original writer performs keyed merge, deduplication and transpose.

The effective fit uses three residual layers, 256 centers per layer, squared Euclidean distance, GPU KMeans++ initialization, a 3,072-vector initialization buffer, a training batch size of 2,048 and SGD with learning rate 0.5. Each residual is normalized before calculating the level assignment. The frozen embedding tensor is used unchanged. Seed 42 comes from the source config. The native TensorFlow row shuffle still calls `shuffle(buffer_size=128)` without an explicit per-call seed. PyTorch uses single GPU FP32 and the native `medium` matrix-multiplication precision setting.

The formal fit uses the original `trainer.max_steps=30`. The native layer-wise schedule divides this into ten Lightning-counted updates per layer. The preview uses six Lightning-counted updates, two per layer, and retains the entire catalogue and full dimensions. Before these counted updates, each layer buffers a first 2,048-vector batch and takes 1,024 vectors from a second 2,048-vector batch to initialize. The raw SGD calls for both initialization batches occur outside the Lightning step counter. The admission check uses the actual trace to verify the distinction, item coverage, all three initialized layers, finite values and post-initialization centroid updates. Historical fit duration is about 140 seconds on the original setup. This timing comes from the historical log and should be considered separately from the current GPU observations.

The original fourth digit assigns 0 to singleton three-code prefixes. For a repeated prefix it assigns 1 through group size in ascending internal item ID order. Inference checks the first three digits against the native prediction callback. It checks the fourth digit against an independent per-prefix implementation and rejects any digit outside the existing 256-slot vocabulary. The catalogue maps all 9,922 original LETTER IDs and ASINs to the new IDs. The downstream entry must verify the SID manifest and bind both data and lookup files to it.

The launcher accepts `fit`, `sid`, `verify` and `config` with the same `--mode`, `--embedding`, `--identity` and `--output` flags. The `config` subcommand renders both effective configs in a distinct output directory with CUDA hidden and constructs no trainer. It records the planned checkpoint name. Actual SID generation resolves its checkpoint from its own verified fit gate and records the file hash. Failed stages retain their original attempt; a later attempt can consume a byte-identical fit stage copied from its predecessor after checking the checkpoint hash and source-relative path. A preview asset cannot pass formal admission.
