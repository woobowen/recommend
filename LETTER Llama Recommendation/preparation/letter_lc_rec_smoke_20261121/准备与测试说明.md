## 原作者补充配方与短测

Beauty 使用 `seqrec,item2index,index2item`，温度 1.0；Instruments 使用 `seqrec`，温度 0.8。两者 LoRA r8/alpha16/dropout0.05、学习率 2e-4、response-only，embedding 与 lm_head 活跃副本参与训练。三个 Beauty 任务都来自作者的原始 Dataset 和 Prompt 实现。

`smoke_test.py` 直接调用作者 `modeling_letter.py`、`data.py`、`prompt.py`、`collator.py`、`evaluate.py`，以短训练循环检查整体流程。每数据集只做 6 次优化器更新；Beauty 每任务 2 次，Instruments 序列推荐 6 次。验证检查两个用户；每种测试条件检查四个用户；固定 beam20，不遇到 OOM 时偷偷降低 beam。

短测顺序：Int8 加载 LLaMA → 扩展 SID token → LoRA/embedding/head 梯度检查 → 六次更新 → 检查 SID embedding 确有变化 → 验证 loss → 保存 adapter → 重新加载主干和 adapter → 对比 logits → 三种顺序生成与指标检查。

短测只用于证明工程流程可执行，少量更新和四用户指标不能当成正式推荐结果。

## 硬件和兼容适配

- GPU0、1：单进程切分同一个模型，依次测试 Instruments 和 Beauty。GPU2、3不分配。
- 使用原作者的 Int8 冻结主干 + LoRA，但 2080 Ti 计算用 FP16，不能照搬 BF16。
- 使用原生 SDPA，跳过原启动脚本强制调用的 FastChat FlashAttention。短测不用 DeepSpeed。
- 运行时仅禁用不使用的 bitsandbytes SwitchBack Triton 导入以及 Accelerate 的无关 DeepSpeed unwrap，保留 Int8 CUDA 实现。PEFT 0.12 读取 bnb 0.46 已移除的 `memory_efficient_backward` 字段时，恢复其 False 默认值；不更改安装包源码。
- FP16 GradScaler 初始 scale128；AdamW 使用普通 Torch 实现，非 8-bit 优化器。
- 短测 token 长度上限 512，单样本更新；正式作者配置是 2048 和批量/梯度累积。显存、吞吐、训练稳定性以真实 7B 短测为准。
- 先用同一种 Int8 主干验证保存重载，logits 最大差值为 0。随后补测未量化 FP16 主干推理，两数据集的三种顺序均通过。作者测试脚本采用未量化 BF16，2080 Ti 适配为 FP16；正式实验应固定并披露精度口径。

## Shuffle 与评价

模型只用正常顺序训练。同一个已保存 adapter 评估 `unshuffle`、`shuffle_3`、`shuffle_4`。只重排历史商品内部的 SID token，保留商品时间顺序、提示词、attention mask、目标与输出 SID 顺序。S3 第四位固定。

根据用户随后要求，现已对齐此前 LETTER-LC-Rec 的 `GRID-LETTER-SHUFFLE-V1` 协议及 seed42：S3 从 5 种非恒等排列选、S4 从 23 种非恒等排列选，每件可见历史商品的整体排列必须改变，但不要求每个位置都移动。协议对 `[protocol,seed,n,row_idx,item_idx,counter]` 的规范 JSON 做 SHA256，使用拒绝采样从按字典序排列的候选中选择；不依赖 batch、rank 或全局随机数状态。

最初小规模测试使用 seed2026 且允许恒等排列，该版代码保存于 `legacy_including_identity/`，原运行配置、指标和证据保持原记录。之后的对齐复测复用相同 adapter，不重新训练；结果写入 `test_fp16_aligned_<mode>.json` 与 `fp16_aligned_verified.json`，不覆盖旧测试结果。此前自有 TIGER 的 `plan_v1_1` 版本也允许恒等排列，不能把它误称为非恒等协议。

作者公开解码代码实际上是按生成位次允许相应层 token，而不是论文文字描述的完整目录 Trie。本次短测保持该代码，并记录候选完整 SID 的目录合法率。指标沿用作者完整 SID 匹配，冲突 SID 商品无法区分。正式与自有 TIGER 比较还需统一 beam、shuffle 协议、训练样本及选模条件。

## 证据文件

- `expected_source_assets.json`：本地冻结来源与预期 SHA256。
- `model_download_verified.json`：服务器实际模型文件下载、长度和 SHA256 验证。
- `assets_audit.json`：下载完成后的代码、数据、模型完整审计。
- `readiness.json`：环境、数据集、tokenizer 和 batch 检查。
- `kernel_preflight.json`：小随机模型上的真实 CUDA 前向、反向与更新检查，与真实 7B 短测分开记录。
- `fp16_inference_verified.json`：两数据集的未量化 FP16 推理检查，与 Int8 保存重载测试分开记录。
- `latest_queue.json`、`runs/<时间>/status.json`：短测队列状态。
- 各数据集 `events.jsonl`、`result.json`、三组测试 JSON 和 `adapter/`：真实模型运行证据。
