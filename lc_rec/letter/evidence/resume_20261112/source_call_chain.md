# Frozen source and observation points

Original method: vendor `lora_finetune.py` / `modeling_letter.py`; present integration is `formal_train.py`. All author values still checked against `author_instruments.json`; formal JSON hash remains `9e058cecb7151ebee3ab714ab8328af0008537156cd96684c988d89e7ee10600`.

1. `formal_train.main`: author `set_seed(42)`, real Instruments datasets, tokenizer+918 SID tokens, LETTER Int8 loading, resize, PEFT int8 preparation, r8 LoRA seven projections and active embedding/head. 450 trainable tensors /289652736 elements. Original frozen modules retained. Existing FastChat/unpad, PEFT out-of-place and224 A-only BF16 guards unchanged.
2. HF4.31 `Trainer._inner_training_loop` creates loader/scheduler and Accelerate0.21 prepares DeepSpeed. `_prepare_deepspeed` passes actual AdamW to DS, wraps optimizer; external HF LambdaLR stays outside DS because it is not a DS native scheduler. Trainer still steps it once at update boundaries.
3. DS0.16.9 stage2 constructs FP32 partition (`single_partition_of_fp32_groups`), bit16 groups and parameter slice mapping. AdamW receives these masters; same-DP load restores original FP32 copies and native optimizer state. S1/S2 compare all optimizer state, not only Adam's underlying dictionary.
4. `ReplayLoader` preserves actual DataLoaderShard sampler/prefetch behavior. Save records epoch-start streams, yielded position, checkpoint RNG, and synchronized generator. Resume reconstructs skipped CPU inputs from epoch-start, restores checkpoint RNG before the next yielded input. `_load_rng_state` intentionally suppresses HF's later restore. Input/label hashes are captured after replay and before Trainer `_prepare_inputs`.
5. HF `_save_checkpoint` calls model save, collective DS checkpoint and native rank RNG; custom extension adds loader and external scheduler, with barriers and complete manifest. Original step2 has19 payload files plus complete manifest. S0 probe occurs immediately BEFORE native save; S1 is actual file content; S2 callback runs AFTER strict load and `model.zero_grad`, before loader replay. `before_first_forward` is AFTER replay, before `super().training_step`.
6. Native `Trainer.training_step` runs model.train → prepare inputs → forward under its configured context → `accelerator.backward(loss)` → returns **loss.detach()/gradient_accumulation_steps**. Thus historical micro-loss values are divided by4; unscaled CE is four times the log value. Accelerate's DeepSpeed backward delegates the original loss to DS, which applies its accumulation scaling and native backward/step. No extra scaling is added by probes.
7. The narrow no_sync shim only gives nullcontext for the guarded ZeRO2/GAS4/world2 engine; it does not suppress native allreduce. DS backward's partition/reduction epilogue populates `averaged_gradients`. Probe S4 is at entry to ZeRO optimizer.step, **after reduction, before unscale/clip and native AdamW**. It records masters and moments as well as reduced gradient hashes.
8. Native stage2.step computes global norm, flattens current partition gradients, casts to FP32, unscales/clips, invokes original AdamW, copies FP32 master into BF16 partition, allgathers bit16 groups, and updates model views. Probe S5 occurs on return from that exact method, before DS engine increments global_steps. Labels explicitly use `step_before_update=2/3` (updates3/4).
9. bnb0.45.5 `Linear8bitLt._save_to_state_dict` saves CB through weight.data and SCB explicitly, whether SCB lives in weight or MatmulLtState. Cold first forward migrates weight.CB/SCB to state and clears weight attributes. This representation difference is expected; canonical effective CB/SCB values must match. `MatMul8bitLt.backward` for frozen weight input gradient reads state.CB/SCB and ctx.dtype_A. Other legacy caches are not inferred necessary without actual reads.
10. FastChat padding path calls `flash_attn_varlen_kvpacked_func` with attention dropout0, causalTrue and default deterministicFalse. Frozen FlashAttention2.7.4 stores the flag in ctx and forwards it to `_wrapped_flash_attn_varlen_backward`. Its docstring states forward is deterministic and offers a separate deterministic backward path. This is a source-backed hypothesis until controlled data proves contribution. DIAGNOSTIC_ONLY overrides only that option through FastChat's actual imported aliases; no installed package is edited.

Coverage boundaries: full serialized module/optimizer state and required RNG are fingerprinted; byte equality is stronger than the floating tolerance. Fingerprint mismatch alone does not measure numerical severity; full final state comparator retains original atol/rtol. Selected projection/head activations and LoRA gradient hooks localize observed divergence, not every unobserved operation. CPU copies synchronize CUDA and can affect scheduling; both paired runs use equivalent probes. RNG snapshots include both visible CUDA streams. Parameter inventory, optimizer membership and DS param slice mapping establish mapping evidence; cross-process raw storage addresses are never compared.
