## 输入、模型及原始候选

用冻结 LETTER item/SID 与交互顺序独立构造 Prompt0，通过冻结 tokenizer 对全量用户逐条重编码。完整词表摘要及 918 个 SID 单 token 的词到 ID 对应与已审输入记录相等。原 Normal rank 0 和 rank 1 各 12,386 行，逐位交织后独立核对全局 24,772 行分配与每条原始 Prompt。两份 Normal JSONL 的完整 SHA-256 与冻结值相等。测试集包含 9,922 项、9,897 个不同完整 SID、23 个碰撞组。

独立程序按紧凑 JSON 与完整 SHA-256 为每个可见历史商品推导相对排列，严格复现允许恒等的 V2 协议。S3a 与 S3b 共享每条三槽相对排列。四条件 99,088 条实际用户记录和 691,716 个历史组条件逐条核对。全部匹配冻结用户、目标、最近 20 条范围、原生组边界、组内完整 token 置换、固定槽、组外内容、显式 mask 和原生 position 摘要。轮中真实模型记录对全部 20 beam 保存实际 prefill 的 input、mask、position 摘要、cache 长度 0 及 beam 一致性断言。

## 离线复核

使用包内既有 tokenizer wheel，不需要安装或联网。将解包后的原始证据路径、该 wheel 和新的本地输出目录传给命令。若包的内容索引存储了同字节多路径，先按包根说明重建逻辑路径。

```bash
bash review-A/reproduce.sh raw /path/to/tokenizers-wheel.whl /tmp/a1-review-a
```

仅在有固定 Git 对象的工作区中追加 `--git-worktree /path/to/worktree`。正式线上和 WSL 用相同固定对象核验时两份输出均逐字节一致。在纯离线环境，`jobs.result.json` 唯一预期差异为 `compared_fixed_git_objects=false`，运行源码仍与包内计划、服务器部署和已存 Git 字节回执核对。线上 CPU 审核实际耗时 52.085 秒，最大 RSS 为 287,940 KiB，见 `server-runtime.json`。

审核工具曾因服务器未安装 `/usr/bin/time` 在导入前退出，改用 Python 自带 `resource` 获取用量。首次资产校验发现审核代码中的 checkpoint 选择回执哈希抄漏两个字符，从固定 CPU asset manifest 与服务器原件核对后修正。部署描述符的主机身份从外层真实服务器回执读取。上述调整仅涉及本次新写的审核脚本，无研究执行或资源预算变化。
