## 2. 工作流、方案依据、授权与低维护

用户决定方向，网页 GPT 设计并二次审核，Codex 执行。默认“概要确认 → 适配/内部审核 → 必要预跑/获授权实验 → 运行中或结果核验后深入讲解”。概要讲清目标、原流程与拟改变的环节；不要求用户先完全听懂代码，也不能把重要研究变化藏在接口修复里。保持后续源码与结果可讲解，不自行标记用户已理解。

复现实验优先沿用王学长针对本次任务的明确方案、对应可核验源码、有效配置和处理方式。模板默认不等于历史生效值，需核实际覆盖；不要自行优化已明确且适用的方案，不从不同历史版本混拼参数后称原版。学长现在的说明决定本次选择，不自动证明过去的运行事实；冲突与缺失如实说明。

按影响分级处理，具体细则见 `PROJECT_RULES.md` 第 3 节：
- 已有适用且无冲突的明确设置，直接沿用并记录依据，不重复询问。
- 低影响工程细节，先有推荐默认与简短理由，在已授权范围内处理；执行中新遇到同类问题可自主选择并记录，不为每个路径、命名或日志格式反复请示。
- 方法、数据/SID/权重、随机化语义、模型参数、训练/初始化/冻结/选模、生成评价、分析口径或较大资源变化的重要未决项，先给首选方案、依据、差异及代价；用户补充学长方案或批准推荐后才实施相关部分。不因代码短或参数名看似工程就降为小事。

推荐依据必须来自实际材料、明确推导或核实过的外部原始资料。不能只抛选择题，也不能伪称推荐就是学长原方案。重要未决项只阻塞其依赖工作，其余已授权部分继续；不先按自选值运行后补报。具体算法、默认参数与未确认方案写入现有任务说明，不固化到长期规则。

授权范围内连续完成工作，不只回计划、不逐步重复请示。原件有问题则保留并说明，涉及实质行为的修正按上述权限处理；不通过未经确认的设置变化解决资源或接口问题。完成本轮终点即停止，不自动扩域或执行下一实验。历史 P0 仅准备的禁令不是永久禁止运行，P0 成功也不授权新训练。

只维护少量长期规范。实验卡可在现有提示词/说明用一小段表达目标、对照、固定输入/版本、方案来源及确认、脚本/配置、指标、预算、验收和停止条件；重要决定原处补充。不新建要求持续人工维护的进度/交接/决策流水账或状态看板。机器 request/status、脚本、日志、配置与原始结果照常保留。新对话交接仅在用户要求时整理一次提示词。

## 3. 分支与代码身份

LC-Rec 使用 `wbw-lc-rec`；旧三条 GRID 线 `wbw`、`wmh`、`yjc` 按用户本次明确授权对应 `wbw-grid`、`wmh-grid`、`yjc-grid`。`main` 及其他协作分支仅按用户明确指定的内容、方向和范围同步；保留 `sid-extensions` 等其他历史分支。不自动新建其他分支、强推、丢弃改动、改visibility/default branch或覆盖他人内容。遇到分叉/归属冲突保存并报告，不绕到新分支解决。

每次正式运行和审核绑定完整commit、实际脚本/源码、有效配置、资产身份。保护运行快照，不能因在对应工作分支继续改代码而改变已启动任务。Git操作由主控串行整合。服务器源码export可能无.git，按文件映射核对，不能假称checkout。push后实际回读远端ref和必要内容；本地commit不等于发布完成。

原件、工程适配、新研究实现分开，原件不静默修补。尽量最小且可审查的diff，不用strict=False掩盖缺失/随机参数。未知源码/历史绑定准确标记，不凭同名配置、相近指标或checkpoint形状造历史。

## 4. 实验正确性与依据边界

本项目研究范围包含 Beauty/Toys/Sports 上的 Shuffle、MLP、非自回归 Parallel 和注意力分析等已确认方向，但名称不构成具体方法或运行授权。先行数据域、顺序和扩域条件按当次任务与审核执行，不要求指标必须提高。已可用 baseline/资产和收口 A800 档案优先复用，但先核是否符合本次学长方案；不自动用现成工程基底替换实验条件，也不自动重训、重生成或重查学弟过去失败的 baseline。

按选定方案核对数据划分、item/SID/权重配对、标签、可见信息与分组、位置/mask、参数共享和迁移、loss、训练选择、生成候选及 evaluator。变化与保持不变的条件分开记录。不导入其他项目的超参数，不用测试集反复挑配置。文件 hash、语义配对、加载/接口成功、完整实验与现象重现是不同结论；指标接近不单独证明代码正确，指标不同也不必然是错误。

代码类名、开关、同名 YAML 或 checkpoint 形状不能证明目标方法已经生效。可开关干预应按方案验证对照一致性和实际变化范围；结构/生成改动须核真实依赖、参数、训练目标和输出。观测与图表须绑定样本、模型、原始记录、路径选择和汇总口径，不挑漂亮图或有利案例冒充普遍规律。具体实现依据已有专题源码与当次确认，不在此预设。

先做必要有界预跑、定向回归，再执行获授权长任务。文档或材料整理任务不夹带模型加载/运行。合成样例、静态推导、历史结果、本轮实测分开，保留失败和不利结果。已知历史缺口或新重建明确标记，不通过调到相近指标伪造历史来源。

## 5. 脚本与服务器独立执行

Codex在WSL，使用既有Windows SSH/SCP连接双4090 `new-server`；不在学校服务器安装/登录Codex，不用sudo，不无故改驱动/框架/VPN/路由/代理/SSH。使用前核卡身份、占用、空间与权限。关键路径和工具读取 `REMOTE_EXECUTION.md`，不假定老文档是实时状态。

正式研究操作写成保存的脚本＋配置，记录实际 argv、解释器、cwd、完整 commit、输入 hash/来源、GPU/seed/预算、日志/结果/退出码，以及采用设置的学长依据或用户批准的补充方案。最终生效值与确认内容对应，必要偏离单独说明。终端只负责调用，不能以 history 或事后补写脚本充当执行证据。轻量只读查询允许直接调用并保存重要输出。

长任务复用已验收runner，在服务器保存程序、输入、日志、状态和固定job_id并脱离SSH/Codex生命周期。不要只加&就宣称安全；确认独立接收/启动、无笔记本必要依赖后才告知可退出。网络不可达/回执丢失先查原ID，不盲重跑；新脚本/输入尝试保留旧身份和失败记录。

Codex在线且具备持续执行条件时每10—20分钟轻量检查真实进程、step/日志、错误、GPU和空间；启动后先确认，异常时有界地缩短检查间隔。等待时只做已授权且无冲突工作。Codex退出后实验和已有服务器看护继续，不假设关闭的AI继续思考；无法持续监控要如实说明并保存入口。重新打开后按原job继续监视或核验完成结果，不自动重启。

恢复监控与恢复计算分开；暂停新增工作不等于取消现有任务。只管理本任务已核实进程，不用宽泛pkill。服务器重启/管理员清理/磁盘故障不承诺无条件自动恢复。

## 6. 排错、预算与真实非作者审核

初次执行为 round 0，随后整个同一任务最多三轮集中定位—修正—复核；不是每问题/每代理各三轮，不换会话重置。已有通过就停，不凑轮次。记录原因、最小修改、影响与复核到现有记录；不降验收标准、不用未授权实验或测试集搜索来“优化通过”。三轮限制不授予三组大型调参预算，重要设置变化仍需确认。权限/安全问题不要求硬试三次。

无法解决的阻塞登记依赖与尝试，继续无依赖工作；三轮后尚有必需缺口则PARTIAL/BLOCKED，不直接忽略。正常有界传输重试与研究改动分开，实质修正后验收要计轮次。

重要复杂任务使用真实可用子代理分工，关键由非作者读原件/代码/执行证据复核，不让多代理并发覆盖同一文件或重复搬大数据。不可用时如实说明，不编造独立PASS。简单维护只做相称的轻量检查。定向回归，不反复全仓审计。

## 7. 数据、空间、秘密与清理

大资产/档案留new-server，WSL保持有限暂存，已有同身份内容复用。校验LFS真载荷、源/目标/暂存容量和路径；临界停止新增写入，不能盲删资料腾空间。二进制不用PowerShell文本管道，Windows工具路径须真实可读。

原件不改、可写副本不与原件共享可改inode。保护正式数据、SID、权重、原日志、凭据、同学工作和活动进程；不扫描无关账户，不将私钥复制到远端或上传GitHub/审核包。

仅按明确清理授权，核对正式目的实体及无活动依赖后逐路径删除临时件。不跟随symlink删目标，不把原档案分块当传输缓存，不使用全目录git clean/gc/LFS prune或清空Temp。用途不明保留；报告逻辑大小与实测释放的区别，保留至少一份用户控制的正式审核材料。

实质代码/配置/脚本、结果与必要审核说明发布对应工作分支（LC-Rec 为 `wbw-lc-rec`，GRID 为 `wbw-grid`），并实际回读固定提交、核服务器对应。报告先结论后逐项证据：动作、改动、结果、job状态、commit/路径、非作者检查、修正轮次、限制和恢复入口。执行退出0不等于产物/研究验收完成；未完成或仍在跑如实写，不在用户要求完整结果时只给计划。

每次最终回复必须给 `GPT_UPLOAD_REQUIRED: YES/NO`。NO：必要材料已在固定GitHub/已提供证据，给完整SHA和入口；YES：先整理校验轻量ZIP，含必要外部回执与引用依据，给真实WSL/Windows路径、大小、SHA-256和说明，不让用户逐个找文件。不要重打整套大档案；检查成员/哈希/秘密，ZIP哈希置包外。小维护无异常可以NO并留小回执。

完成当前授权即停止，不自动同步 `main` 或其他协作分支、开新分支、扩域、训练新模型或整理一套进度文档。用户要求时才生成新对话交接提示词。深入讲解可后置，但最终发布材料必须支持网页GPT沿真实代码解释原流程、diff、张量/参数/训练生成、影响与局限。
