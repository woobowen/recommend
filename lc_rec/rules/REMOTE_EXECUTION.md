标准文件名使用大写 `AGENTS.md`。本项目采用用户已经选择的根目录布局，不要求为了旧路径说明新建 `docs/`：

```text
/home/addaswsw/recommend/
├── AGENTS.md
├── PROJECT_RULES.md
└── REMOTE_EXECUTION.md
```

这三份文件是本地规则正文。`/home/addaswsw/recommend` 与实际 Git 工作副本 `/home/addaswsw/recommend-worktrees/sid-extensions-p0` 不是同一目录，也不互为父子目录。不要假定换一个同级目录启动后会自动读取这套规则；在相关会话中先确认实际读取的来源、版本和适用范围。

从 `recommend` 入口工作时，先读同目录三份规则，再操作实际 Git 工作副本。直接从 Git 根启动时，应显式读取上述统一入口；若已有经过用户同意的短引导 `AGENTS.md`，按其指向读取即可。不存在的引导文件不能写成已部署，本规范也不自动授权新增或覆盖其他目录的 AGENTS/override。无需复制多套详细规则或移动整个仓库。

当前 Codex 在 WSL 中运行，SSH 只是提交/查询服务器任务的工具。因此本方案把规则读取放在本地会话，不将“向 new-server 上传 AGENTS.md”作为本地遵守规范的前提；如果将来改成远端运行 Codex，再按新的明确方案安排规则入口，不自行改变架构。

首次相关任务只做必要的小型读取确认：当前目录、实际 Git 根、适用的 AGENTS/override、两份规范来源和版本。全局旧条款与项目要求可能有差异时，先比较实际原文及适用范围，不凭概述将整份全局规则废弃，不修改 `~/.codex` 来影响其他项目。具体项目要求按用户最新明确确认执行，但不能覆盖更高优先级指令、权限或安全限制。

新增/修改规则后，当前会话应显式重读受影响条款或新开会话确认，不假定热更新已经完成。规则不可读时说明影响，继续无依赖的安全工作，不凭记忆补规则。本节不要求额外维护进度、交接或代理配置文档。

## 3. 正式操作脚本化：终端用于调用，不作为唯一记录

训练、测试、干预、注意力采集/绘图、数据批处理和正式结果汇总，都应有可保存、可重跑的脚本入口与参数配置。代码放对应工作分支（LC-Rec 为 `wbw-lc-rec`，GRID 为 `wbw-grid`）的适当已有目录，避免为每个 seed 复制整套代码。复用公共脚本，实验差异放配置；确认过的运行方式不能只留在 Shell history 或 Codex 对话里。

写好并检查脚本后再提交，不能先跑临时命令、事后补一个相似脚本冒充原入口。必要命令参数以实际 `argv` 保存，避免引号/空格丢失。记录有效配置，包括模板、Hydra overrides、环境中会影响实验的必要项及最终生效值；排除秘密和无关环境变量。

执行方案依 `PROJECT_RULES.md` 第 3 节确定：优先采用本次适用的学长明确方案及对应有效配置，运行脚本和最终生效值必须与确认内容对应。既有模板或现成工作资产不自动决定本次方法。对必要偏离，在现有任务说明中记录采用值、依据、差异和确认状态，不另建配置审批系统。

低影响路径/输出安排等给出推荐与简短理由，在已授权范围内处理；不能为适应设备、显存、依赖或目录问题，静默改变有研究影响的设置。涉及模型、数据、训练、随机化、生成评价、分析口径或较大预算的未决变化，先提出有依据的首选方案并取得用户确认。重要项未确认时只暂停相关依赖任务，不按自选值先运行后补报。

轻量一次性只读查询可直接调用已有工具，不为每条 `ls` 新建脚本；重要判断保存输出。复杂安装/同步/修复有明确输入输出和操作记录，必要时也脚本化。脚本须有明确 cwd、解释器、输入检查、输出目录、错误传播和可识别退出码；不吞掉异常，不把管道最后一步的成功当训练成功。

每个正式 run 的必要记录如下，尽量复用已有 request/status/log，不重复制造人工表格：

| 类别 | 最小信息 |
|---|---|
| 身份 | 实验/任务名、host/account、稳定 job_id、attempt、关联父尝试与时间戳/时区 |
| 代码 | 固定 commit、实际脚本路径/字节身份、工作目录、必要未发布差异 |
| 调用/配置 | 解释器、实际 argv、有效配置、种子、监控间隔、预算和时限；对应方案/参数来源及必要偏离的确认依据 |
| 输入 | 数据划分、item/SID 映射、checkpoint、来源清单与必要内容身份 |
| 环境/资源 | 实际 GPU 标识与可见设备映射、关键依赖版本、并发和磁盘预算 |
| 输出 | stdout/stderr、阶段进度、metrics、checkpoint/预测/attention位置及产物清单 |
| 终态/审核 | 真实退出码、成功/失败/超时/取消、收尾、产物检查及是否待审核 |

隐私与凭据只记录来源/变量名，不转储秘密值。失败尝试保留，修正后新 attempt 或关联 job_id；不得复用旧成功请求身份却替换脚本、输入或结果。

## 4. 长任务必须在服务器独立运行

优先复用已验收的 task runner/transport。已有本地 `.../sid-extensions-p0/scripts/gridctl.py` 是定位线索，先核对真实文件、`--help`、目标、版本和状态存储位置，再用于新任务；不盲套旧命令、不改写冻结 P0 回执。新实验沿现有机制使用独立 job 和输出，不另造大型调度平台。

提交前必须完成：必要代码/配置/输入在服务器就绪；GPU/磁盘/权限和依赖明确；固定源码快照；预跑和本轮授权门槛满足；脚本不依赖笔记本文件服务或临时代理继续供给输入。需要服务器联网的步骤另核出网条件，不能把“本地现在能联网”当成服务器长期依赖可用。

任务程序和监督/必要看护与 SSH 会话脱离，stdin 不等待终端，stdout/stderr 持续写服务器文件。要有稳定请求身份、任务锁/防重、真实进程身份、退出状态和时限。只加 `&`、仅开一个终端或只看到 PID 不算可靠证据；已有机制需证明提交连接结束后还能在新连接找到原 job 及其结果。

收到请求、已启动、正在计算、已完成是不同状态。向用户表示“可以关闭本地”前，确认服务器真正接收并独立启动，而且没有依赖未完成的本地传输。脚本需传递子进程失败；仍有本任务 worker 写出结果时不能过早打完整成功标记。

本地 Codex、SSH、WSL 或校园 VPN 退出，不应主动取消已接受的服务器作业。原始远端程序和日志可以继续，后续 AI 分析则仍需相应会话。服务器重启、管理员清理、磁盘故障或自身代码失败不在无条件完成保证内；需要恢复时依据保存进度，而不是宣称任何中断都“无损自动恢复”。

## 5. 监控：在线每10—20分钟轻量检查，离线保留可接续记录

Codex 在线且具备持续执行条件时，正常长实验每 **10—20 分钟**轻量查询一次，具体间隔写入当次配置/实验说明，可选 15 分钟。提交后先做一次启动确认；短预跑或已发现异常可采用更短的有界检查。每次观察记录时间，不将旧记录当当前状态。

检查原 job 的实际进程、阶段/step/epoch、最近日志与错误、GPU/显存概况、输出空间及最近产物。按阶段判断进展，不能因瞬时利用率低、验证耗时长或 loss 未改善就自动认定死锁。只有满足已约定故障/安全条件才处理；不盲目 kill/restart、不自动变更研究协议。

查询需轻量：读取增量/末尾日志，不每次拉全部输出、不重读全模型、不对巨大数据反复哈希、不另跑一次评测。关键异常及时简短汇报，正常等待不刷大量“仍运行”消息。等待期间可以做已授权、无冲突、不抢占必要资源的分析/记录整理，不能为显得忙而启动未授权实验或改运行快照。

本地退出后，实验及已有服务器监督继续保存进度和终态。需要离线资源采样时，复用已有看护或获授权的轻量服务器脚本，输出到同一任务记录；不要求已关闭的 Codex 定时醒来，不另建常驻 AI 管理系统。当前工具/会话无法持续检查时如实披露并保存接手入口，不能虚构定时监控。网页 GPT 不承担后台轮询或定时通知。

重新打开 Codex 后恢复监视；若已经完成，在原授权内核验结果并返回，不再次提交整任务。终态已确定即停止无意义轮询。

## 6. 断线、暂停、失败与恢复

重连顺序：读当前任务原始记录 → 用原 host/account/job_id 查询 → 比较状态、真实进程、日志和产物 → 继续监控、核验结果或按权限修复。收到用户交接提示词后也遵守这一顺序，不把提示词当实时服务器状态。

| 情形 | 正确处理 |
|---|---|
| 提交响应丢失 | 原 ID 先查接收和执行情况，禁止换 ID 盲目重复。 |
| 网络不可达 | 保存最后已知状态与本次查询失败；不把实验改判失败/成功或已停止。 |
| 进程仍正常 | 接续监控，不启动重复进程，不覆盖输出。 |
| 真实退出成功 | 检查预期产物、范围、配置/指标和子进程收尾，再进入任务审核。 |
| 失败或超时 | 保留日志/退出码，定位原因，在已授权修正预算内处理。 |
| RUNNING与进程不一致 | 检查 pid身份/启动时间、监督记录和产物，不能只看pid数字或状态字符串。 |
| 需要从checkpoint恢复 | 记录恢复点、旧新尝试、优化器/随机状态等实际恢复内容，不能默认宣称等价从头跑。 |
| 用户只暂停后续工作 | 不再提交新任务，保存记录；是否停已运行任务单独确认。 |

监控查询和计算恢复是不同操作。失败后的修改与重新验收纳入 `PROJECT_RULES.md` 的任务级三轮限制，不因断线、换会话或改 attempt 重置。不可解阻塞只阻断依赖任务，其余安全工作继续；不越权修系统、扫无关账户或暴力认证。

## 7. GPU、环境与任务隔离

正式用卡前刷新占用和设备身份，遵守实验室安排；两个24GiB级设备不自动等于可用于单卡模型的48GiB。记录物理设备与 CUDA_VISIBLE_DEVICES 映射，不永久指定“GPU0总是我们的”。满足依赖且已授权的独立任务可按实际空闲资源并行；观测任务依其实际需要的模型/产物安排，绘图和已保存结果统计尽量使用适当的 CPU 资源。性能测量单独控制资源竞争。

只在授权范围使用服务器资源、下载模型或安装依赖。优先现有解释器和已验证组件；新增必要用户级依赖记录包/版本/来源/原因/验证及影响，不重装驱动、CUDA或公共框架，不无故重复GPU smoke test。原件不能直接编辑；派生工作代码与归档隔离，不用可写硬链接共享原件 inode。

每个运行有独立输出目录和固定源码/配置。并行代理不可互相覆盖；不要在训练进程读取的工作树里持续 pull 或改 Python。同步只到明确目录，禁止全HOME镜像、自动传播删除或覆盖同学工作。正式科研作业不在 WSL 笔记本上顺便长跑。

显存、时间或依赖不足时，先定位，再按方案影响分级处理。不能自行改变有效 batch、精度、历史长度、搜索预算或模型结构以获得成功标签；这类变化已在本次任务中明确批准的，按批准方案执行并记录。紧急资源保护使用已约定安全停止条件，不以实验继续为由损害共享环境。

## 8. 传输、空间、原件与清理

大型数据、checkpoint、完整档案以 new-server 为主，WSL保留编辑代码、轻量证据和有限暂存。先预算源、目的、压缩/展开及临时副本空间；留安全余量，临界时停止新增写入并保存进度，不等磁盘写满。与本次已确认方案匹配的实体优先复用，不因新对话再 clone 全部 LFS 或下载无关上游大模型。需要不同实验资产时先确认范围，不能因现成副本方便就擅自替代。LFS指针不等于真实工作载荷。

沿现有 Windows SSH/SCP 通道传输；Windows程序的本地文件参数须是实际可访问路径，不能把任意 WSL `/home/...` 当Windows路径。二进制不经过会转码的PowerShell文本管道。中断后使用已设计的固定分块和hash/manifest接续；普通SCP重传不是文件内部自动断点续传。

临时件先用临时身份，完整校验后发布为正式产物。原件档案、可写工作副本、结果和临时传输件用途明确，注意符号链接、硬链接与访问权限；哈希一致只证明内容身份，不证明语义或运行正确。按约定来源捕获保持版本，变化文件另记，非原子遍历不得声称原子快照。

清理只在明确授权范围：正式目标已存在并完成必要校验、候选没有活动依赖、精确路径归属清楚后删除一次性临时件。禁止沿symlink删除目标、把A800完整档案分块误作LFS传输缓存、清空整个Temp或直接删除研究支持目录。保留原件、必要checkpoint、脚本/配置、最终回执、日志和至少一份用户控制的审核包；聊天附件不是唯一长期备份。身份不明就跳过，不能为了整齐停进程、改权限或扩大删除范围。

简单清理只做小范围核对和简短回执，不重建multi-agent长任务、全量重hash几十GB或重打大包。记录删除/迁移/逻辑大小与实际物理释放的区别；只在实测时声称释放量。
